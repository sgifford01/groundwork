## 1. Purpose and career fit

Entitlement is the stage where a developer learns what can be built, how long permission will take and what it will cost. It is where most land value is created and most early-stage money is lost. An analyst needs to compute capacity from zoning standards, know which approval path a project is on, recognise when a state housing law changes the answer, and put a number on delay. The student is at UC San Diego, so the local frame is California and the City of San Diego.

## 2. Learning objectives

1. Given a lot and zoning standards, the student can compute maximum floor area and unit count and name the binding constraint. (`entitlements-zoning`)
2. Given setbacks, coverage and height, the student can compute a buildable envelope; given parking ratios, required stalls. (`entitlements-zoning`)
3. Given a project description, the student can say whether an approval is an entitlement or a permit, and discretionary or ministerial, and what that means for timing and appeal risk. (`entitlements-approvals`)
4. Given a project, the student can describe in outline how CEQA applies (exempt, negative declaration, EIR) and why the level of review drives schedule risk. (`entitlements-ceqa`)
5. Given a project and one state housing law (Density Bonus Law, SB 9, SB 35 / SB 423, ADU law), the student can decide whether it applies and compute what it changes. (`entitlements-state-law`)
6. Given a fee schedule and a unit mix, the student can compute impact fees and compare an inclusionary on-site obligation with an in-lieu fee. (`entitlements-local`)
7. Given the City of San Diego's process, the student can place a project in the right decision process and name who decides and who can appeal. (`entitlements-local`)
8. Given a timeline, carry costs and outcome probabilities, the student can compute expected cost, the bad case, and a probability-weighted land value. (`entitlements-risk`)

## 4. Key concepts, definitions and formulas

Generic definitions (safe to teach without citing a jurisdiction):

- **Zoning** regulates use and intensity. **Entitlement** is the right to build a particular project; a **building permit** confirms the construction drawings comply with codes.
- **Ministerial** (by-right): the agency checks objective standards and must approve if they are met; no discretion, usually no public hearing. **Discretionary**: the decision-maker weighs the project and may deny or condition it; hearings and appeals are possible.
- **FAR** = floor area / lot area. **Density** = units per unit of land. **Lot coverage** = footprint / lot area. **Setback** = minimum distance to a property line.
- **Binding constraint:** of several limits, the one that produces the smallest result.
- **Carry cost:** what it costs to hold a site while waiting (option payments or interest, taxes, insurance, consultants).
- **Expected value** = sum of probability x outcome.

#### Example 1: Buildable floor area: FAR vs. height and coverage (`ent-ex-capacity`)

Floor area ratio (FAR) = total floor area / lot area. Height and lot coverage form a second, independent limit: storeys x footprint. The smaller result governs.

| Given | Name | Value |
|---|---|---:|
| Lot area (SF) | `lot_sf` | 20,000 |
| Maximum FAR (hypothetical) | `far` | 2.00 |
| Height limit, ft (hypothetical) | `height_limit` | 50 |
| Floor-to-floor height (ft) | `floor_to_floor` | 10.0 |
| Maximum lot coverage (hypothetical) | `coverage` | 60% |

| Step | Name | Formula | Result |
|---|---|---|---:|
| Floor area allowed by FAR | `by_far` | `=lot_sf*far` | 40,000 |
| Storeys under the height limit | `storeys` | `=ROUNDDOWN(height_limit/floor_to_floor,0)` | 5 |
| Footprint allowed by coverage | `footprint` | `=lot_sf*coverage` | 12,000 |
| Floor area allowed by height and coverage | `by_envelope` | `=storeys*footprint` | 60,000 |
| Buildable floor area | `buildable` | `=MIN(by_far,by_envelope)` | 40,000 |

*Note.* Here FAR binds (40,000 SF against 60,000 SF). A height increase would add nothing; a FAR increase would.

The percentages, the income levels and the rounding rules come from the statute and MUST be looked up at build time. The figures below are placeholders.

| Given | Name | Value |
|---|---|---:|

| Affordable set-aside, % of base (PLACEHOLDER) | `set_aside` | 10% |
| Bonus earned, % of base (PLACEHOLDER) | `bonus_pct` | 20% |

| Step | Name | Formula | Result |
|---|---|---|---:|
| Affordable units | `affordable` | `=ROUNDUP(base_units*set_aside,0)` | 4 |
| Bonus units | `bonus_units` | `=ROUNDUP(base_units*bonus_pct,0)` | 8 |

| Given | Name | Value |

## 5. Common misconceptions

1. The largest limit governs → the smallest does (every standard must be met).
2. FAR counts the footprint only → it counts all floors (check the code's own definition of floor area; exclusions vary).
3. Height limit divided by floor height is rounded to the nearest storey → a partial storey does not fit.
4. Zoning approval is a building permit → they are separate; one is about what, the other about how.
5. "By-right" means no review → there is still review against objective standards.
6. Discretionary and ministerial are about project size → they are about whether the decision-maker has discretion.
7. CEQA approves or denies projects → it is a disclosure and mitigation process attached to discretionary decisions.
8. A density bonus set-aside is measured on the total units → on the base units (verify in the statute).
9. Bonus units replace market units → they are added on top of base density.
10. An in-lieu fee is always the cheap option → compare it with on-site cost and with what on-site units unlock.
11. Expected cost is the cost of the most likely case → it weights every case.
12. A delay costs only carry → it also defers the payoff (time value).
13. Fee schedules are stable → they are re-adopted, often annually; always quote the date.
14. Applying the probability to the whole timeline rather than only the uncertain extra months.

**Learned in Chunk 1 (2026-11-15).** The statute pages on leginfo.legislature.ca.gov read well as text in the browser pane, and each shows the last amending statute. **How to read the City's PDFs (found after Chunk 1; no installs needed).** Fetch the PDF with WebFetch, which saves the file and reports its path, then extract its text with the PDF engine built into macOS:

```bash
osascript -l JavaScript -e "ObjC.import('PDFKit'); var d = \$.PDFDocument.alloc.initWithURL(\$.NSURL.fileURLWithPath('/path/to/file.pdf')); d.pageCount + '\n' + d.string.js" > out.txt
```

The text keeps the edition date from each page header (for example "Chapter 13: Zones (9-2026)") and the tables read row by row with their footnote numbers (Table 131-04G came through cleanly). Record the edition date in the log next to the check date, and read the footnotes before using any number from a table.
